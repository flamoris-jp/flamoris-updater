# FLAMORIS Updater 1.0.13

Keeps everyday application management compact: catalog registration and all source URLs move into collapsed Catalog Management; old executable deletion remains accessible. The newest compatible update is selected first, while older installed releases are excluded from install/update choices.

The operator view shows only Jobs admitted after the server served that page. Previous active, failed and completed Jobs stay in the read-only Job Search screen, with application and creation-period filters, bounded paging, and existing durable effect details. Each tab and reload has its own insertion-order boundary; browser clocks and progress changes cannot pull older Jobs into that view. Old unresolved self-updates still block operations.

Opening/reloading the screen or pressing Refresh checks the official Updater catalog and installed applications' recorded GitHub Release origins. Progress polling reads saved snapshots. Sources are deduplicated, failed sources retain their checked snapshots/status, and explicit removal persists across restarts. Unknown/non-unique origins require manual catalog registration; app names are never converted to repository guesses.

Self-update compatibility: 1.0.3 through 1.0.12; the existing bootstrap supervisor and v1 journals remain compatible. No automatic application update, history deletion, database migration, GPU transition or credential provisioning is introduced by opening/searching these screens. Source/CI verification and production acceptance are separate.
