# FLAMORIS Updater 1.0.15

Adds optional confined DRM render-node access for managed Docker applications, including Kachinco CLI VAAPI encoding. A recipe may select one `/dev/dri/renderDNNN` character device. Preflight validates its kernel identity and non-root group permissions; startup passes only that node and group, and runtime verification checks the exact binding. No privileged mode, arbitrary devices, host permission changes or GPU runtime switching are introduced.

Empty device selections preserve existing CPU profiles. Updates retain application settings, data and the originally selected device. Applications remain responsible for actual codec/driver probing and physical GPU acceptance.

The native bundle build now reads the package version instead of a second hard-coded release number. Publication retains immutable tags: this new release contains the DRM source change; existing 1.0.14 assets are never replaced.

Self-update compatibility: 1.0.3 through 1.0.14. Existing v1 journals, the pinned bootstrap supervisor, application profiles and persistent data remain compatible. Source/CI, publication and real-host acceptance are separate.
